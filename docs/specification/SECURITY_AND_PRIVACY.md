# Data Ownership, Security & Privacy

## Threat model (V1)

- 내부 연구, 가격, 계약, R&D, 기업용 문서가 **PC 로컬 또는 웹 브라우저 로컬**에 존재할 수 있음.
- 직접 파일 불러오기, 제3자 Markdown/HTML, 첨부, ZIP import가 주 위험 경로.
- 배포 저장소 및 정적 번들로 데이터 유출 가능.
- PWA/브라우저 저장소 회수, 디스크 손상, 클라우드 미구현으로 인한 기기별 사일로가 데이터 손실 위험.

## V1 Security controls

- 최소 권한 Tauri 파일 접근: 선택된 워크스페이스 범위만 허용, symlink 및 경로 탈출 검증.
- 렌더된 Markdown HTML을 안전하게 sanitize. raw HTML 기본 비활성 또는 엄격 제한, 콘텐츠 보안 정책(CSP).
- ZIP unpack: traversal (`../`, 절대경로, 드라이브 prefix), 파일 수, 확장자, 크기/총압축해제량 및 심볼릭 링크 제한.
- 업로드 파일 MIME/type 검증, 실행/스크립트 형식 격리·프리뷰에서 실행 금지.
- 비밀키/API token/실회사 문서/개인정보 `.gitignore`, 앱 자산, Pages 배포물에 포함 금지.
- 버전별 의존성 audit + lockfile, release checksum.
- 문서 삭제는 기본 휴지통; 백업/복구의 **성공**이 확인되기 전 원본 제거 금지.
- 사용자가 허용한 경우만 외부 네트워크 사용. 업데이트 체크/진단 로그에 문서 본문 전송 금지.
- 모바일 EXIF 위치정보 제거 옵션과 원본 보존 여부 명시.

## Device limitation notice

- PC 로컬 저장은 해당 컴퓨터 사용자 계정/디스크 보안과 암호화 상태에 좌우됨.
- IndexedDB/OPFS는 백업이나 서버 원장과 동일하지 않음. 브라우저 데이터 삭제, 저장소 정책, 기기 교체 시 소실될 수 있음.
- 초기 앱에서 두 기기 데이터의 자동 동기화가 된다고 안내해서는 안 됨.
- 향후 조직 계정·권한은 원격 동기화 서버 도입 시 서버에서 실질 검증해야 함. UI 숨김으로 권한 보호 불가.

## Future audit/approval design policy (V3)

- 승인 완료 원본은 대표이사를 포함 누구도 수정하지 못하도록 **append-only 개정/승인 구조**로 구현.
- 역할별 감사 로그 열람은 허용 범위 내로 제한.
- 정책/권한/감사 설정 변경 권한은 대표이사에게만 부여하되 변경 자체도 감사 추적.
- 기록된 감사 로그는 대표이사를 포함 누구도 수정·삭제할 수 없도록 독립 저장/검증 설계.
- 단일 로컬 PC의 SQLite row 잠금은 불변성을 보장하지 않음. 서명, 독립 보관, WORM/장부형 감사 등 실증 필요.
